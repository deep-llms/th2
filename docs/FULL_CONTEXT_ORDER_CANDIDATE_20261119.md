# Candidate: separate layer routing from context restriction

Not admitted or launched. Decide after route-gradient final report/replay/handoff. Prior outputs and controls remain immutable. This is a distinct architecture hypothesis, not a claim that the current window implementation is incorrect.

The current window protocols intentionally restrict the four middle attention blocks to each strided window. Only stem and coda have full context. Their matched GF/LF controls isolate learned ordering within that architecture, but comparison against six full-attention dense blocks also changes context access. Our code inspection identifies this confound; it does not establish that removing it will create a routing advantage.

Primary sources rechecked18Nov2026: [Library of Layers](https://arxiv.org/html/2611.03526v1) describes strided-window whole-block routing; our alternative below deliberately changes that design. [Mixture-of-Depths](https://arxiv.org/abs/2404.02258) studies dynamic token compute allocation, a different intervention from choosing whole-block identity. Neither paper is evidence that the proposed candidate will win.

Candidate forward: at each of four middle depths, every candidate block attends causally to the **entire shared input hidden prefix at that depth**, using its own Q/K/V projections. Select the output block separately for each causal window. Route features still use only preceding windows (the first window may use its first token). All candidate forwards use the same fixed full-sequence tensor shape. There is no exchange or reuse of KV tensors across different experts. This is a dense reference implementation of routed blocks; it is not sparse compute and makes no speed claim.

Start from one verified full-attention dense six-layer parent per seed, copying stem, four middle blocks, coda, embeddings and output norm. A per-depth router prior initially selects canonical0,1,2,3. Use unit hard residual scale so the initial canonical model is exactly the dense parent. Contrast fixed canonical order F, hard routing with selected-only surrogate derivative H, and hard routing with all-candidate surrogate derivative S. For H/S let the hard residual be delta[e]; add a forward-zero term sum_k(p[k]-stopgrad(p[k]))*stopgrad(delta[k]), masked to k=e only in H. S uses all candidates. These are biased surrogate gradients, not RL, not differentiable hard decisions, and not the selected-probability forward used by LoL. Body gradients flow directly only through the selected candidate. Both H/S have the identical hard forward and differ only in the router derivative.
