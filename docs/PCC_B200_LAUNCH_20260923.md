## Distributed implementation and validation

`run_experiments.py` already allocates arbitrary physical GPU lists and is reused.
`pcc.joint` launches single-node torchrun with eight workers and no automatic
restarts. Only rank zero publishes logs/checkpoints/completion; all ranks save
RNG state and restore their own state on resume. Validation uses disjoint
contiguous row ranges, with no padding or duplicate examples, and reconstructs
original per-context order before comparisons. Non-reentrant activation
checkpointing is retained. See the
[PyTorch DDP reference](https://docs.pytorch.org/docs/stable/generated/torch.nn.parallel.DistributedDataParallel.html).

Real two-process Gloo tests passed for all three arms: accumulated updates agree
with the single-process global reference, replicas agree, uneven/padded eval
is exact, and interrupted/resumed Deep weights equal uninterrupted weights
bit-for-bit. The B200 capacity gate additionally checks actual pretrained native
no-op equivalence, updates in early/late/branch weights, full replica hashes,
checkpoint roundtrips, and a distributed next-update resume smoke for Deep.

The legacy `train.py` uses HF Trainer and still contains unrelated EmbHub
imports. It is not used for this custom PCC experiment. Its historical shell
example is not a current node/configuration specification.
