For each source: sort parquet paths, Python `Random(2029).shuffle`, take the declared prefix, retain published row order inside each file. This is randomized **shard selection**, not a global document shuffle. Exact source paths/sizes/HF LFS SHA256 and resolved revision URLs are pinned in `resources/a2_corpora_30b_20261029.json`. The bounded source reserve is expected to provide ~40Btokens per corpus; exact GPT-NeoX counts determine when processing stops. Extra raw shards may remain unused. Never repeat documents to fill an insufficient pool; fail explicitly and extend the source manifest if needed.

## Tokenization and splits

Use the existing checkpoint GPT-NeoX tokenizer, SHA256 `c24618a1b3e6a38167beff1c72cffd126c3a66254347304b50547d12c5f25624`. Verify all three tokenizer files against the existing A2 provenance. `add_special_tokens=False`, no BOS, no tokenizer truncation/padding, append EOSid0 to every nonempty document. Empty/whitespace-only rows are counted and skipped; no length/quality filter is added.

Document split is deterministic across both corpora: SHA256 of exact UTF8 text, first8bytes big-endian modulo10000. Buckets0–1 are tuning,2–9 final,10–9999 heal. Exact-text duplicates therefore cannot cross these split boundaries, including across corpora. This is not fuzzy deduplication, and source duplicates within a split are not removed. It does not establish exclusion from parent pretraining or the old CulturaX evaluation pool. Treat the new corpus's held-out sets as new evaluations and retain old results separately.

Continuous concatenation and4096-token packing across documents **and source shards**. Truncate only at the final full-sequence budget, not per worker batch/shard. Per corpus:

Small set:256tuning rows chosen with NumPy default_rng(2029), indices sorted. uint32LE token streams plus uint8document-start streams match native `PackedRows`. Boundaries retain document starts; cross-document causal attention behavior is unchanged. ~150.1GB final packed output per corpus. Raw inputs and resumable per-shard tokenized staging are retained, so peak disk use exceeds the~300GB final pair.

## Execution and verification

Controller `#d` alone downloads public raw parquet inputs. No external network access from B200. Preparation runs in a CPU-only tmux session using existing `a2_env`, CUDA visibility empty; no GPU/burn reclaim or environment installation. Workers32for DCLM and16for FineWeb-Edu (capped at half CPU affinity), one tokenizer/native math thread per worker. Source files can arrive asynchronously; workers wait for full expected bytes and verify SHA256 before reading. Up to48hours bounded waiting/processing; early progress determines a measured ETA. CPU data work is separate from the historical Phase0A GPU budget.

The worker freezes its script, dependencies and source manifest outside the code sync root. A file lock prevents duplicate preparation. Each shard has an atomic completed receipt, source identity, stream hashes/counts and49-byte document index records (row:uint64, textSHA256:32bytes, token_count:uint64, group:uint8). Completed shards are reusable only after checking their output hashes; incomplete directories are preserved and refused, not overwritten. Coordinator takes deterministic source-prefix tokens irrespective of worker finish order. Final full output hashes and native reader smoke checks must pass before top-level `complete.json` is published. Download existence or tmux liveness alone is not readiness.
