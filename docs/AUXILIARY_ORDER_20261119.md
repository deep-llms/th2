Authorized by the user's request to keep improving and consider auxiliary router learning during warm-up. Follows `warmup_DOT_idea_sketch.md` and `ROUTER_AUXILIARY_NEXT_20261119.md`. Progressive curriculum is negative: even WL oracle is worse than dense. Therefore this tests joint body adaptation, not a claim that a frozen router can overcome that measured oracle bound. Preserve all outputs; reconcile progressive compact export/local replay before admission.

Eight continuations: D/U/G/A × two seeds,2000updates of batch32/length512/prefix32, initialized from the same-seed newly verified progressive D endpoint. Paths are canonical [0,1,2,3] and adjacent last-pair swap [0,1,3,2]. Every arm computes both sequence NLLs on every training batch and the same detached causal prefix features, with the same row order, optimizer/LR and full information labels. The router task is predicting per-example centered two-path NLL. Labels use training suffix targets; router inputs never see scored suffix tokens. This is supervised contextual cost regression, not RL.

D body uses canonical loss only; U body uses uniform two-path mean throughout. G/A bodies use the same uniform mean for first500updates, then weights 0.05+0.90*softmax(-predicted_cost/0.02), detached from the router. G has only two global learned scores; A predicts two scores from prefix features using LayerNorm→128SiLU→2MLP. U and D use the same contextual head as A but the head cannot affect body training. All heads learn from update0 with centered-NLL MSE, and target costs/features are detached from body. Thus U controls auxiliary supervision without feedback, G controls global adaptive order weighting, and D is the continued dense control. Both route losses remain in the computation graph in every arm, including D's zero weight on swap. Count the two body passes and prefix feature pass; do not claim sparse training or generation speed.

No teacher/KD or changes to the existing block architecture. Reserved unique training rows exclude both parent-training row sets and entire router-fit/validation documents; historical documents can recur between parent training and continuation.
